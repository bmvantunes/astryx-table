# Astryx 0.6.5 resize/reorder reuse assessment

Source-only assessment of the installed published package and retained implementation/tests, 2026-10-03. No browser reproduction, tests, builds, repository edits, or Git operations were performed. Paths below identify the inspected sources, not hypothetical APIs.

## Decision

Keep native `TableHeaderCell`, `TableRow`, `TableCell`, and the existing sticky presentation integration. Use the public **`Divider` as the resize handle's presentation**, with our existing width owner, gesture lifecycle, and TanStack keyboard adapter. A native icon-only `Button` can present reorder. Do not install `useTableColumnResize` for this virtual renderer: its exposed controls cannot delegate preview geometry or keyboard handling, and controlled final widths do not solve that gap. Astryx supplies an order/visibility projection plugin, but no Table column drag/reorder engine.

### Public resize seams and their limits

The public package subpath exports `useTableColumnResize` and its config; the declarations expose only `columnWidths`, `onColumnResizeEnd`, global `minWidth`/`maxWidth`, and `columns`. The actual `ResizeHandle` is a private function. `HeaderCellRenderProps.overlay` can carry the plugin's element, but that element still encapsulates all its private behavior; it is not a presentation-only handle API. [Package export](../../node_modules/@astryxdesign/core/package.json:517), [published config](../../node_modules/@astryxdesign/core/dist/Table/plugins/columnResize/useTableColumnResize.d.ts:2), [private handle](../../node_modules/@astryxdesign/core/src/Table/plugins/columnResize/useTableColumnResize.tsx:300), [overlay creation](../../node_modules/@astryxdesign/core/src/Table/plugins/columnResize/useTableColumnResize.tsx:832).

### Public Divider is a suitable presentation adapter

`DividerProps` extends `BaseProps<HTMLDivElement>` and exposes a ref. The root forwards events, `tabIndex`, and `aria-valuenow/min/max`, then sets `role="separator"` and the requested orientation. Its only hook is `useId`; it owns no pointer/keyboard engine, measurement, or width state. The internal line consumes upstream border/color tokens. [Props](../../node_modules/@astryxdesign/core/src/Divider/Divider.tsx:37), [render](../../node_modules/@astryxdesign/core/src/Divider/Divider.tsx:142), [line styles](../../node_modules/@astryxdesign/core/src/Divider/Divider.tsx:82), [BaseProps](../../node_modules/@astryxdesign/core/src/BaseProps.ts:23).

Use `orientation="vertical"`, no label/full-bleed, the exact accessible resize name, snapshot bounds/value, active-header roving tab stop, and our pointer/focus callbacks. Add only root hit-area, shrink, cursor, touch-action, and visible focus styles through `xstyle`. No child selectors, cloning, or private handle imports are required. Verify the wider interactive root and its visible line in the Browser; do not mistake the default approximately one-pixel line for a sufficient hit area. Reorder can use public `Button` with icon/label, `type="button"`, and forwarded pointer props. [Button props](../../node_modules/@astryxdesign/core/src/Button/Button.tsx:245), [render](../../node_modules/@astryxdesign/core/src/Button/Button.tsx:788).

### Reorder capability

`useTableColumnSettings.transformColumns` filters and sorts according to controlled `activeColumnKeys`. Its companion hook offers toggle/reset/set operations and accepts a caller-owned list. Neither implements pointer drag, pinned-region crossing, geometry, autoscroll, focus handoff, or typed atomic reorder commands. This is a usable controlled projection for native full Table consumers, not a missing drag engine hidden behind a callback. [Projection](../../node_modules/@astryxdesign/core/src/Table/plugins/columnSettings/useTableColumnSettings.tsx:86), [operations](../../node_modules/@astryxdesign/core/src/Table/plugins/columnSettings/useTableColumnSettingsState.tsx:194).

Adding that projection here would not remove the existing runtime: it must still preserve hidden-column order, independent pinning, sparse durable widths, resets, and grouped-layout restrictions. Keep the existing typed command path rather than introduce another ordered list solely to reuse a filter/sort wrapper. [Current width owner](../../packages/table/src/internal/column-management.ts:498), [atomic reorder](../../packages/table/src/internal/column-management.ts:524), [settled ownership](../../migration/reference/docs/grid/architecture.md:727).

## Minimal integration plan

1. Add native Divider presentation to the existing native header. Wire the existing TanStack `resize` command to snapshot bounds, logical RTL delta, one `column.resize.commit`, and an announcement. Restore menu width/move/reset commands through the same runtime. Preserve active-header focus and tab-stop behavior. [Retained keyboard implementation](../../migration/table/src/internal/astryx-table-view.tsx:3562), [existing bindings](../../packages/table/src/internal/hotkey-adapter.ts:170).
2. Extract/adapt the retained column gesture workflow into a private module rather than transplant the old large renderer. Its XState actor decides START/COMMIT/CANCEL/INVALIDATE; its observable projection uses Store. Pointer coordinates remain imperative. Reuse the already-available `previewColumnWidth`/`clearColumnWidthPreview`, frame/environment subscriptions, and logical scrolling. Preserve one pending preview frame, exact pointer ownership, final-coordinate fallback, cancellation and teardown. [Actor](../../migration/table/src/internal/column-gesture.ts:18), [retained preview/finish](../../migration/table/src/internal/astryx-table-view.tsx:2369), [current adapter](../../packages/table/src/internal/react-compiler-adapters.ts:255).
3. Add native reorder Button presentation with the same gesture owner. Use mounted rectangles only for hit testing, mapped to stable identities in the full logical order. Retain edge autoscroll, refresh geometry after the new window commits, atomic target index+pinning, suspended-layout pin preservation, and bounded focus restoration. Width/reorder previews must affect header, centre, and both pinned body regions through the existing geometry variables. [Retained reorder logic](../../migration/table/src/internal/astryx-table-view.tsx:2238), [autoscroll reconciliation](../../migration/table/src/internal/astryx-table-view.tsx:2268).

## Evidence to retain

- Keyboard bounds, RTL handle/grid shortcuts, and active-header tab stop: [retained tests](../../migration/table/src/column-management.browser.test.tsx:1966).
- Resize exposing an unmounted centre slice and retained-padding geometry: [tests](../../migration/table/src/column-management.browser.test.tsx:1716).
- Both pinned boundary resizes, one typed commit, zero preview persistence, and bounded mounted work/style writes: [boundary tests](../../migration/table/src/column-management.browser.test.tsx:2384), [performance fixture](../../migration/table/src/column-management.browser.test.tsx:2628). Keep the current production gates; the historical research note describes diagnostic timings, not permission to relax today's gates.
- Reorder across pinned boundaries, centre-gap unpinning, suspended centreless layouts, RTL, and geometry refreshed after autoscroll: [cross-region tests](../../migration/table/src/column-management.browser.test.tsx:1597), [suspension test](../../migration/table/src/column-management.browser.test.tsx:2320), [autoscroll test](../../migration/table/src/column-management.browser.test.tsx:2907).
- Final pointerup before rAF, modified Escape scoped to the owning table, stable gestures under same-shape live data, pointercancel/unmount cleanup, and focus that never steals an external destination: [lifecycle tests](../../migration/table/src/column-management.browser.test.tsx:3008), [live publication](../../migration/table/src/column-management.browser.test.tsx:3273), [focus](../../migration/table/src/column-management.browser.test.tsx:3359), [teardown](../../migration/table/src/column-management.browser.test.tsx:3599).

This is composition through supported public primitives, not a workaround inside Astryx's resize engine. Reusing that engine later would require an upstream presentation/gesture delegation seam, not increasingly invasive DOM interception.
