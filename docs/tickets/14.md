# 14. Performance and emitted-package release gates

## What to build

A release candidate is proven from actual artifacts, ready for an explicitly authorized npm release.

## Acceptance criteria

- [ ] Run complete static/Node/Browser/source/emitted type/build suite and original realistic production performance profiles.
- [ ] Retain 8.33 ms p99, profiling, sample completeness and mounted-window evidence; never replace performance with smoke tests.
- [ ] Verify clean installed tarballs, CSS side effects/import order, SSR/hydration, no-Effect consumer and optional adapter.
- [ ] Audit release source snapshots, file modes/deletions/environment isolation and known source follow-up findings; repeat independent packing.
- [ ] Fresh review covers migration changes. Record npm scope/version/credentials and require explicit publication authorization; verify registry only after actual publish.
